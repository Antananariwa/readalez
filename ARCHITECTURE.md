# Architecture

The code's stable shape, in the form of [matklad's ARCHITECTURE.md](https://matklad.github.io/2021/02/06/ARCHITECTURE.md.html): a bird's eye view, a code map that names the important files and types, and the invariants. It leaves out how each part works. Significant technical decisions: [docs/adr](docs/adr/).

## Bird's eye view

What the app does: [SPEC.md](SPEC.md). In the code, `src/core/` reads pasted text and EPUB files into a book's text, and turns that text into words with their durations, as plain TypeScript (ADR 0003). `src/ui/` plays the words with React and keeps the library in the browser's storage, in a PWA (ADR 0002).

## Code map

Each area names its main files and types. The files it leaves out are their helpers. Search by name finds every file and type named here.

### `src/core/`

The reading logic, with its unit tests beside it (`*.test.ts`) and their texts in `fixtures/`. `epub/testZip.ts` builds ZIP files for the tests and for `scripts/build-books.ts`; the app doesn't use it.

- **Adding books:** `paste.ts` reads pasted text (`parsePaste`). `epub.ts` reads an EPUB file into sections and a chapter list (`parseEpub`, `Chapter`, ADR 0009), with its parsers in `epub/`.
- **Words:** `text.ts` splits a book's sections (`Section`) into the words the reader shows (`Word`, `splitText`).
- **Timing:** `durations.ts` gives each word its duration (`Timing`), from the values in `timingValues.ts`. `schedule.ts` plays the words on a fixed schedule.
- **Reading flow:** `readingFlow.ts` holds the reading flow over the words (`Flow`), its parts (`Part`, ADR 0011) and where chapters start.
- **Library and positions:** `library.ts` holds what the library knows about a book (`BookInfo`). `bookId.ts` names a book by the SHA-256 of its words (ADR 0007). `position.ts` holds a position (`Position`) and the progress and time left saved with it (ADR 0008). `builtInBooks.ts` is the built-in books' catalog, generated by `scripts/build-books.ts` (ADR 0013).
- `webApis.d.ts` declares the web APIs core may use (ADR 0009).

### `src/ui/`

React components, and the code that uses the page, the browser's storage and the service worker. `main.tsx` starts the app.

- **Screens:** `App.tsx` switches between the library (`Library.tsx`), the Add text screen (`AddText.tsx`) and the reader (`Reader.tsx`), in React state with no router. It also joins core to storage: it stores new books, opens them, and fetches a built-in book's EPUB on its first open.
- **Reader:** `Reader.tsx` holds the reader's controls. Each element of the screen has its own component, named for it, such as `WordFrame.tsx` for the word frame. `usePlayback.ts` holds the playback state and controls (`PlaybackControls`) and runs the `requestAnimationFrame` loop that drives `schedule.ts`.
- **Storage and import:** `storage.ts` keeps the library in IndexedDB (ADR 0007), positions included (ADR 0008). `importEpub.ts` reads an EPUB file with import progress (`readEpub`), for an import and for a built-in book's first open (ADR 0013).
- **Offline:** `registerServiceWorker.ts` registers the service worker that `vite-plugin-pwa` builds from `vite.config.ts`. The same config writes the web app manifest and precaches the built-in books (ADR 0006, ADR 0013).
- `styles.css` holds the layout, including where the focus point sits, and the light and dark themes.

### Other folders

- `public/`: files served as they are, including the icons' source `icon.svg` and the built-in books' EPUB files in `books/`.
- `scripts/`: Node scripts. `build-books.ts` builds the built-in books and their catalog (`npm run books`, ADR 0013). `render-icons.ts` renders the app icons (`npm run icons`). `append-review.ts` adds a merged PR's review to `docs/reviews.md`, run by `.github/workflows/reviews.yml`.
- `e2e/`: Playwright tests against the production build, one spec file per area, with shared helpers in `helpers.ts` (ADR 0005, ADR 0010).
- `tests/`: unit tests that read files, which tests in `src/core/` can't (ADR 0009). They check the built-in books against their catalog, the test books in `fixtures/epub/`, and the repo's tooling and settings in `tooling/`.
- `.devcontainer/`, `.claude/`, `.githooks/` and `.github/`: the dev container (ADR 0004, ADR 0012), Claude Code's agents, hooks and settings, the commit hook, and the CI workflows with the issue and PR templates.

## Invariants

- `src/core/` imports nothing from `src/ui/`, React or Node's modules. It uses no browser or Node globals apart from those declared in `src/core/webApis.d.ts` (ADR 0003, ADR 0009).
  Enforced by `npm run check`, through `tsconfig.core.json` and `.oxlintrc.json` (ADR 0005).
- `src/ui/` holds no reading logic (ADR 0003).
- A book is stored parsed and never parsed again, so a change to the paste or EPUB parsers reaches only books added after it. Its ID is computed once, when it is added. Its words are split again at every open, and a stored position is found again in the new split (ADR 0007, ADR 0008).
- The app sends no requests to other sites (SPEC.md feature 13, ADR 0006). `e2e/pwa.spec.ts` checks it for loading the app.
